# Radar Estratégico — WP24H MD Importer — 20/08/2026

## P1 — WordPress 7.1 final já está disponível; chegou a hora de substituir o gate em RC pelo gate contra a build final

### O que aconteceu

O cronograma oficial marca **19/08/2026** como a data de release do WordPress 7.1 e, na coleta de 20/08, a página oficial de download já oferece explicitamente **WordPress 7.1**.

O `wp24h-md-importer` continua declarando:

```text
Tested up to: 7.0
Stable tag: 1.2.0
```

Portanto, o sinal que vinha sendo acompanhado nos radars anteriores mudou de estado: não é mais “aguardar a build final”. A build final está disponível e pode ser usada como evidência real de compatibilidade.

### Impacto específico no projeto

O plugin toca áreas que merecem smoke/regression test em uma major do WordPress:

- criação e atualização de posts;
- Markdown/front matter;
- taxonomias e metadados;
- endpoint REST autenticado;
- capability checks;
- sideload de featured images;
- reutilização de attachments por source URL;
- telas administrativas.

WordPress 7.1 também fecha o ciclo imediatamente posterior à security release 7.0.4. O WordPress 7.0.4 corrigiu um RCE autenticado Author+ via upload malicioso em instalações que usam Imagick e Ghostscript; a equipe do WordPress informou que o fix seria backportado para 7.1 RC3 antes da release final.

Isso **não indica uma vulnerabilidade no WP24H MD Importer**. É apenas uma razão adicional para validar cuidadosamente o fluxo de mídia contra o core final, já que o plugin usa as APIs de media sideload.

### Risco / oportunidade

**Risco: médio até a validação.** Não há regressão conhecida afirmada neste radar, mas declarar `Tested up to: 7.1` sem executar o gate reduz a qualidade da evidência.

**Oportunidade: alta.** Depois do gate verde, o plugin pode declarar compatibilidade de forma verificável e o processo pode virar um conteúdo técnico útil para WP24Horas: “como validar um plugin próprio contra WordPress 7.1”.

### Ação recomendada

Executar hoje uma matriz mínima com **WordPress 7.1 final**:

1. ativação/desativação;
2. import Markdown mínimo e completo;
3. create/update pelo mesmo slug;
4. categorias/tags/excerpt/SEO metadata;
5. REST desabilitado por padrão;
6. REST habilitado + autenticação válida;
7. negativas de capability (`edit_posts`, `publish_posts`, `upload_files`);
8. featured image em PNG/JPEG/WebP;
9. redirects/URL inválida/host inseguro na imagem remota;
10. reutilização do attachment ao reimportar a mesma source URL;
11. logs PHP/REST sem novos warnings/notices;
12. regressão rápida em WordPress 7.0.4.

Se passar, atualizar `Tested up to: 7.1` em commit separado da documentação do radar e registrar a versão/PHP usados no teste.
